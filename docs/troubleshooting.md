# 问题排查与日志采集

## 先确认边界

| 现象 | 首先检查 | 不要立即做的事 |
|---|---|---|
| 功能显示“未应用” | 已开启该功能；对应目标服务已在开关后重启；LSPosed 静态作用域含 MiLink/Mirror | 不要仅凭开关状态认定 Hook 已加载 |
| 平板找不到手机 | 同账号、网络、蓝牙/WLAN、系统原生互联状态与附近发现 | 不要把远端手机能力强制改为平板能力 |
| 通知点击串流失败 | 先从桌面普通应用流转验证认证、密码和设备信任 | 不要绕过或伪造 Xiaomi 的认证流程 |
| 竖屏窗口正确但首帧横向 | 确认竖屏功能已应用到 Xiaomi Mirror；复现时从竖屏状态开始 | 不要通过延迟旋转或反复强制尺寸修复后续帧 |
| 第二台平板无法建立通道 | 手机端同名选项开启；Multi-Channel 已应用到 MiLink Core | 不要伪造 Host 或无条件返回绑定成功 |

## 状态为何会暂时是“未应用”

状态来自已加载目标进程的受校验报告，而不是开关或 LSPosed 数据库。开关保存成功、目标进程尚未冷启动、私有签名不兼容、或功能关闭时，状态都可能显示未应用。点击“重启服务”会停止 MiLink 与 Xiaomi Mirror，并清除旧证据；它们下次启动后才会重新报告。

每个功能对应不同进程：通知流转是 MiLink Notification，竖屏流转是 Xiaomi Mirror，Multi-Channel 是 MiLink Core。因此一个功能成功不代表其余两个也已加载。

## 安全地收集日志

外部设备出现“平板找不到手机”时，使用诊断分支构建并一次完成以下流程：

1. 在 LSPosed 确认模块作用域包含 MiLink，并允许把模块日志输出到守护进程；
2. 在 HyperConnect Toolkit 开启“记录详细日志”；
3. 点击“重启服务”，重新进入系统跨设备流转设置页；
4. 保持手机与平板的账号、WLAN 和蓝牙处于问题发生时的真实状态，点击刷新并等待至少 30 秒；
5. 不要先用其他方式建立串流或改变认证状态；
6. 返回模块，点击“导出诊断日志”，保存文本文件后发送该文件。

报告自动包含模块、Android/HyperOS、LSPosed、MiLink、Xiaomi Mirror、Continuity SDK 和系统设置组件版本，以及当前 LSPosed 作用域。注入端只记录布尔判定、数据长度、设备类型和会话内哈希；导出时还会自动处理常见账号、网络和设备标识。不要上传 OEM APK、完整 framework JAR、反编译源码或签名文件。

完成复现后关闭“记录详细日志”并再次重启服务；关闭状态不会安装额外发现观察 Hook。

## 恢复步骤

如果启动后服务不断崩溃：

1. 在 LSPosed 关闭 HyperConnect Toolkit；
2. 重启设备；
3. 确认 MiLink、Xiaomi Mirror 与普通应用流转恢复原生行为；
4. 重新启用时只打开默认的通知流转功能；
5. 逐项启用其他功能，并在每项之后重启服务和测试。

若无法进入系统界面，请使用 root/LSPosed 环境提供的安全模式或模块恢复机制。不要删除系统应用或替换系统文件。
